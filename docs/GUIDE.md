# Multibox 설치와 사용 안내

QA 용 안내입니다. Apple silicon Mac(M1 이상)에서 쓸 수 있습니다.

## 1. 설치

터미널에 한 줄이면 설치됩니다. "열 수 없음" 안내 없이 바로 열리고, 업데이트도 쉽습니다. Homebrew 가 없다면 https://brew.sh 를 먼저 설치합니다.

```bash
brew install --cask cola9k1/multibox/multibox
```

항상 위처럼 전체 이름(`cola9k1/multibox/multibox`)으로 설치하세요. Homebrew 는 외부 저장소의 앱을 전체 이름으로 지정할 때만 그 앱을 신뢰하므로, 짧은 이름 `multibox` 로는 막힐 수 있습니다.

`/Applications/Multibox.app` 에 설치됩니다. 예전에 dmg 로 `~/Applications` 에 설치한 Multibox 가 있다면 지우세요. 같은 앱이 두 개로 보입니다.

Homebrew 를 쓰지 않는다면 이 문서 맨 아래의 "부록. dmg 로 직접 설치"를 보세요.

### 업데이트

새 버전이 나오면 앱을 열 때 `업데이트 가능` 창이 뜹니다. 닫으면 이번 실행에서는 다시 뜨지 않고, 다음에 앱을 열 때 다시 알려 줍니다.

알림을 놓쳤거나 지금 버전이 궁금하면 `환경 점검` 탭 맨 위의 `Multibox 버전` 에서 확인합니다. 지금 버전이 보이고, `업데이트 확인` 을 누르면 최신 버전인지 알려 줍니다. 새 버전이 있으면 `업데이트` 버튼이 나오고, 누르면 위와 같은 안내 창이 열립니다. 확인하지 못했다고 나오면(오프라인이거나 GitHub 요청 한도) 잠시 뒤 다시 눌러 보세요.

- Homebrew 로 설치했다면 `업데이트` 버튼을 누릅니다. 앱이 종료되고 Homebrew 로 업데이트한 뒤 다시 열립니다. 1분 정도 걸리고, 열려 있던 테스트 브라우저와 로그인 상태는 사라집니다. 터미널에서 직접 하려면 아래를 실행합니다.

  ```bash
  brew update && brew upgrade --cask cola9k1/multibox/multibox
  ```

  업데이트 뒤 앱이 다시 열리지 않거나 버전이 그대로면 `~/Library/Application Support/multibox/update.log` 에 원인이 남아 있습니다.
- dmg 로 설치했다면 `내려받기` 버튼으로 릴리즈 페이지를 열어 새 dmg 를 받고, 같은 방법으로 다시 설치합니다. 이전 앱을 덮어씁니다.

알림은 앱을 시작할 때 한 번 확인합니다. 인터넷에 연결되어 있지 않으면 알림이 뜨지 않습니다.

## 2. 처음 실행하면

웹 테스트는 설치만 하면 바로 쓸 수 있습니다. 앱 테스트(iOS 시뮬레이터, Android 에뮬레이터)는 준비가 필요하고, 그 준비는 앱이 안내합니다.

앱 위쪽의 `환경 점검` 탭을 열면 준비된 항목(`준비됨`)과 필요한 항목(`필요`)이 순서대로 보입니다. `필요` 항목을 위에서부터 차례로 해결하세요. 항목마다 해결 방법과 복사해서 붙여넣을 명령이 있고, 명령 옆의 `터미널에서 실행` 을 누르면 같은 탭 아래의 터미널에서 바로 실행됩니다. 관리자 암호(`sudo`)는 그 터미널에 입력하세요. 입력한 글자는 보이지 않는 것이 정상입니다. 끝나면 `다시 점검` 을 누릅니다. 앱 테스트 탭에 기기가 하나도 없을 때도 `환경 점검 열기` 버튼이 같은 곳으로 안내합니다.

미리 알아 둘 것은 큰 다운로드입니다.

- iOS: Xcode(App Store, 무료, 용량이 큼)와 iOS 시뮬레이터 런타임(약 16GB 이상)이 필요합니다. Command Line Tools 만으로는 안 됩니다. 런타임은 앱 테스트 탭의 `OS` 구역이나 Xcode > Settings > Components 에서 받습니다.
- Android: Android Studio 로 준비하거나, Homebrew 가 있으면 앱이 명령줄 도구로 대신 준비합니다(아래 `Android 준비`). Android 는 iOS 와 달리 버전마다 시스템 이미지를 내려받아 가상 기기를 따로 만들어야 하고, 만든 가상 기기는 앱 테스트 탭에 버전별로 나타납니다.
- 웹 테스트만 한다면 이 준비는 필요 없습니다. iOS 나 Android 한쪽만 쓴다면 쓰는 쪽만 준비하면 됩니다.

처음 실행했는데 준비되지 않은 도구가 있으면 `환경 설치` 화면이 먼저 열립니다. iOS, Android 를 고르고 `시작하기` 를 누르면 앱이 막힌 항목의 명령을 차례로 실행하고 다시 점검하면서 끝까지 진행합니다. 관리자 암호(`sudo`)는 화면 아래에 나타나는 터미널에 직접 입력하세요(입력한 글자는 보이지 않습니다). 앱이 대신할 수 없는 것(Xcode 는 App Store 로그인이 필요합니다)은 이유와 `App Store 에서 Xcode 열기` 버튼을 보여 주고, 설치한 뒤 `다시 시도` 를 누르면 이어서 진행합니다. 웹 테스트만 쓴다면 `건너뛰기` 로 닫아도 됩니다. 다시 열려면 `환경 점검` 탭의 `환경 설치` 를 누릅니다.

### Android 준비

**방법 A. 앱이 대신 설치 (권장, Homebrew 필요)**: 첫 실행의 `환경 설치` 화면(또는 `환경 점검` 탭의 `환경 설치`)에서 Android 를 고르고 `시작하기` 를 누릅니다. 앱이 Homebrew 로 명령줄 도구(`android-commandlinetools`)와 Java 17 을 설치하고, `sdkmanager` 로 `Platform-Tools`, `Emulator`, `Build-Tools`, `arm64-v8a` 시스템 이미지를 받고, `avdmanager` 로 기본 가상 기기를 만듭니다. Android Studio 는 필요 없습니다. 이미지는 용량이 커서(약 1~2GB) 시간이 걸립니다. Homebrew 가 없으면 https://brew.sh 를 먼저 설치하세요.

**방법 B. Android Studio 로 직접**

1. Android Studio 를 설치하고 한 번 실행해 Android SDK 를 내려받습니다. https://developer.android.com/studio
2. SDK Manager 에서 `Android SDK Platform-Tools`, `Android Emulator`, `Android SDK Build-Tools`, 그리고 `ARM 64 v8a System Image` 를 설치합니다. Apple silicon 은 `arm64-v8a` 이미지만 씁니다.
3. 가상 기기는 앱 테스트 탭의 `기기 추가` 에서 만들 수 있습니다(Android Studio 의 Device Manager 도 됩니다). Android 는 iOS 와 달리 버전마다 시스템 이미지를 내려받아야 하는데, 앱 테스트 탭의 `OS` 구역에서 받을 수 있습니다. `환경 점검` 탭의 `Android 버전` 항목이 지금 어떤 버전이 있는지 알려줍니다.

## 3. 사용 방법

### 웹 테스트 (설치만 하면 바로 사용)

왼쪽에서 설정하고, 오른쪽 패널에 테스트 브라우저가 앱 안에 나란히 열립니다.

1. 왼쪽의 `주소`에 테스트할 주소를 입력합니다. `localhost:3000` 처럼 개발 서버 주소도 됩니다.
2. `사이즈`를 고릅니다. 웹 테스트는 실제 기기가 아니라 브라우저를 그 화면 크기로 맞춰 보여주는 것이라 "사이즈"라고 부릅니다.
   - `휴대폰`: iPhone 17 Pro Max, iPhone Air, iPhone 17, iPhone 16 / 15, iPhone 14, iPhone SE, Galaxy S25 Ultra, Galaxy S25, Galaxy A 시리즈, Pixel 10, Android 소형
   - `태블릿`: iPad Pro 13", iPad Pro 11", iPad Air 11" / iPad, iPad mini, Galaxy Tab S9, Android 태블릿
   - 직접 입력: `너비`, `높이`(CSS 픽셀), `배율`(화면 선명도)을 직접 바꾸면 목록이 `직접 입력`으로 바뀝니다. 너비와 높이는 100~4000, 배율은 1~5 안으로 맞춰집니다. 그 옆 화살표 버튼은 너비와 높이를 서로 바꿔서 세로와 가로 방향을 전환합니다. 화면 종류(iPhone, Android, iPad 등)에 따른 사용자 에이전트는 마지막으로 고른 프리셋의 것을 씁니다.
   - 사이즈는 테스트가 실행 중일 때 바꿔도 바로 적용됩니다. 페이지를 다시 열지 않으므로 쿠키와 로그인 상태가 유지되고, 페이지가 새 크기로 다시 배치됩니다(휴대폰에서 태블릿처럼 사용자 에이전트가 달라지는 종류로 바꿀 때만 새로고침합니다).
   `테스트 창 갯수`는 칸에 숫자를 직접 입력합니다(1~50). 세션 하나가 브라우저 프로세스 하나라서 세션당 메모리를 약 100MB 씁니다(50개면 약 5GB). 메모리가 넉넉하지 않은 Mac 에서는 갯수를 줄이세요.
3. `화면 배치`에서 배치 모양 그림을 눌러 고릅니다. 그림은 실제 배치 모양이고, 현재 배치는 파란 테두리로 표시됩니다.
   - `바둑판`: 같은 크기의 칸으로 나눕니다. `열 수`를 비워 두면 화면이 가장 크게 보이는 열 수를 자동으로 고르고, 숫자를 넣으면 그 열 수로 맞춥니다.
   - `가로형`: 브라우저를 옆으로 나란히 한 줄에 놓습니다. 카드가 약 200px 보다 좁아질 만큼 많으면 줄을 나누지 않고 카드 크기를 유지한 채 가로로 스크롤합니다.
   - `세로형`: 브라우저를 위아래로 쌓아 한 열에 놓습니다. 카드가 약 180px 보다 낮아질 만큼 많으면 열을 나누지 않고 카드 크기를 유지한 채 세로로 스크롤합니다.
   - `메인 + 오른쪽 목록`, `메인 + 아래 목록`: 첫 브라우저가 영역의 2/3 를 차지하고 나머지는 옆이나 아래에 한 줄로 나열됩니다. 목록이 길면 메인은 그대로 두고 목록만 스크롤합니다.
   - 스크롤 중에는 영역 안에 온전히 들어온 브라우저만 화면이 보이고(나머지는 숨지만 입력은 계속 따라 합니다), 카드를 끌어 옮기거나 크기를 바꿀 수 없습니다. `자유 배치`로 바꾸면 가능합니다.
   - `자유 배치 (직접 조절)`: 아래 4번처럼 직접 옮기거나 크기를 바꾸면 자동으로 이 방식이 됩니다.
4. 브라우저 카드를 직접 조절할 수 있습니다.
   - 위치 바꾸기: 카드 제목줄을 끌어서 빈자리에 놓습니다. 다른 카드 위에 놓으면 두 카드의 자리(와 크기)가 서로 바뀝니다.
   - 크기 바꾸기: 카드의 오른쪽 가장자리, 아래 가장자리, 오른쪽 아래 모서리를 끕니다. 맞닿은 카드는 분할 창처럼 경계선이 같이 움직이고, 직접 줄일 때 한 카드는 오른쪽 패널 폭(높이)의 8분의 1 아래로는 줄어들지 않습니다. 다른 카드와 겹치게 되는 변경은 적용되지 않습니다.
   - 카드가 좁으면 제목이 사라지고, 아주 좁으면 닫기 버튼만 남습니다.
   - 앱 창 크기를 바꾸면 카드도 같은 비율로 따라 바뀝니다. 테스트 창 갯수를 실행 중에 바꾸면 늘린 만큼 새 브라우저가 열리고, 줄이면 뒤에서부터 닫힙니다.
5. `보기 방식`에서 두 가지를 고릅니다.
   - `사이즈 그대로`: 페이지는 지정한 사이즈 그대로 그려지고, 카드가 작으면 비율을 유지한 채 줄여서 보여줍니다. 페이지가 보는 화면 크기와 배율은 지정한 값 그대로입니다.
   - `칸 크기에 맞춤`: 카드 크기만큼의 화면으로 그립니다. 카드를 키우거나 줄이면 페이지가 반응형으로 다시 배치되므로 화면 폭별 동작을 볼 때 씁니다.
6. `테스트 시작`을 누르면 오른쪽 패널에 그 갯수만큼의 브라우저가 앱 안에 열립니다.
7. 브라우저마다 쿠키와 로그인 상태가 따로입니다. 서로 다른 계정으로 동시에 테스트할 수 있습니다.
8. 세션 이름은 기본으로 `세션1`, `세션2`, ... 입니다. 카드 제목을 누르면 그 자리에서 이름을 고칠 수 있습니다(Enter 저장, Esc 취소, 비우면 기본 이름으로 돌아갑니다).
9. 각 브라우저 위의 아이콘으로 그 브라우저만 다룹니다. 마우스를 올리고 잠깐 기다리면 기능 설명이 말풍선으로 나옵니다. 왼쪽부터 기준 삼기(전파 모양), 새로고침(돌아가는 화살표), 개발자 도구(꺾쇠 모양), 닫기(X)입니다.
   왼쪽의 `모두 새로고침`과 `테스트 종료`는 전체에 적용됩니다. `테스트 종료`를 누르면 브라우저의 쿠키와 저장소는 사라집니다. 테스트 중에는 `테스트 시작` 버튼이 `이 주소로 이동`으로 바뀌고, 주소를 바꿔 누르면 브라우저를 그대로 두고 주소만 옮기므로 쿠키와 저장소가 남습니다. 인증 쿠키를 주고 다른 주소로 리다이렉트하는 개발용 우회 경로처럼, 한 주소를 거친 뒤 다른 주소로 가야 하는 흐름도 이렇게 테스트합니다.
10. 왼쪽 설정 패널은 접을 수 있습니다. 패널과 브라우저 영역 사이의 세로 띠(`<` 모양)를 누르면 패널이 접히고 브라우저 영역이 그만큼 넓어지며, 브라우저도 넓어진 영역에 맞춰 다시 배치됩니다. 접힌 상태에서는 띠(`>` 모양)를 눌러 다시 펼칩니다. 접은 상태는 기억합니다. 접은 동안의 알림은 화면 위쪽 오른쪽에 나옵니다.
11. 단축키: Cmd+R 모든 브라우저 새로고침, Cmd+[ 뒤로, Cmd+] 앞으로.

주의: 이 브라우저는 Chromium 엔진입니다. 화면 크기, 터치, 사용자 에이전트는 해당 기기처럼 보이지만 iOS Safari 와 완전히 같지 않습니다. Safari 에서만 생기는 문제는 앱 테스트 탭의 iOS 시뮬레이터에서 Safari 로 확인하세요. 페이지에 `viewport` 메타 태그가 없으면 실제 폰처럼 980px 너비로 보입니다.

### 앱 테스트

왼쪽에서 기기와 앱을 고르고, 오른쪽에 기기 화면이 나란히 열립니다. iOS 와 Android 를 함께 열어 같은 앱을 한 화면에서 비교할 수 있습니다(최대 6개). 왼쪽 패널은 위쪽 탭으로 `기기`, `앱`, `도구` 세 구역으로 나뉘고, 마지막에 본 구역을 기억합니다.

1. `기기` 구역은 `iOS` 와 `Android` 로 나뉘고, 각각 최신 버전부터 `iOS 26.5`, `Android 17 (API 37)` 처럼 버전별로 묶여 보입니다. 꺼져 있는 기기의 `켜기` 를 누릅니다. 처음에는 몇 분 걸릴 수 있습니다. 켜지면 그 기기의 화면이 오른쪽에 자동으로 뜹니다. 이미 켜진 기기는 `화면 보기` 로 띄웁니다. 별도의 시뮬레이터 창은 열리지 않습니다.
   - `+ 기기 추가` 로 새 기기를 만듭니다. `OS 버전`, `기기` 모델, `이름` 을 고르고 `만들기` 를 누릅니다(Android 이름은 영문, 숫자, `_`, `.`, `-` 만 됩니다). 만든 기기는 `내 기기` 에 보이고, 위쪽의 `내 기기` / `전체` 로 이 앱에서 만든 기기만 볼지 시스템의 모든 기기를 볼지 고릅니다. 만든 기기가 하나도 없으면 `전체` 가 기본입니다.
   - 각 기기의 `⋮` 메뉴에서 `이름 바꾸기`, `초기화`(iOS, 앱과 데이터를 모두 지움), `삭제` 를 합니다. 이 앱에서 만든 기기만 가능하고(Xcode 나 Android Studio 에서 만든 기기는 그대로 둡니다) 삭제와 초기화는 한 번 더 확인합니다.
   - Android 기기를 만들려면 시스템 이미지, `avdmanager`, Java 가 필요합니다. 부족하면 대화상자에 이유가 나옵니다.
2. `앱` 구역의 `새 앱 설치` 에 `.app`, `.ipa`, `.apk` 파일을 끌어다 놓거나 `파일 선택` 으로 고릅니다. 가상기기에서 실행할 수 있는 빌드인지 바로 알려줍니다. 파일에 맞는 종류의 기기(`.apk` 는 Android)가 자동으로 선택됩니다.
3. `설치할 기기` 를 확인하고(기기 구역에서 고른 기기와 같습니다) `선택한 기기에 설치하고 실행` 을 누릅니다. 같은 종류의 켜진 기기가 둘 이상이면 `켜진 ... 기기 N대 모두에 설치하고 실행` 도 나타납니다. 맨 위에 `검사`, `변환`(실기기용 iOS 빌드일 때만), `기기 켜기`, `설치`, `실행` 단계가 차례로 표시되고, 실패하면 막힌 단계가 빨갛게 남습니다. 설치한 앱은 `설치한 앱` 에 카드로 남습니다.
4. 설치한 파일은 앱 안에 사본으로 보관됩니다(앱마다 최근 5개, 같은 파일은 한 번만). 그래서 원본을 옮기거나 지워도 다시 설치할 수 있고, 카드 아래의 `버전` 선택에서 이전 버전을 고르면 버튼이 `설치하고 실행` 으로 바뀌어 그 버전을 설치하고 실행합니다(여러 버전을 비교할 때). 카드 아래의 기기 선택 상자에 실행될 기기가 보이고 바꿀 수 있습니다(같은 종류의 기기만 나옵니다). `삭제` 는 목록과 보관한 파일만 지우고 기기의 앱은 그대로 둡니다. 기기에 앱이 없으면 보관한 사본으로 다시 설치합니다.
5. `도구` 구역에 딥링크, 화면 캡처와 녹화, 기기 상태, 기기 로그, 웹 디버깅이 있습니다.
6. `OS` 구역에서 설치된 iOS 시뮬레이터 런타임과 Android 시스템 이미지를 크기와 함께 보고, 지우고, 받습니다. `iOS 시뮬레이터 > + 받기` 는 버전을 입력하면 그 버전(예: 18.5)을, 비우면 설치한 Xcode 에 맞는 최신 버전을 받습니다(약 8GB, Xcode 필요). `Android 시스템 이미지 > + 받기` 는 받을 수 있는 목록(인터넷)에서 고릅니다. 받는 동안 진행 줄과 `중단` 버튼이 나오고 한 번에 하나만 받습니다. 런타임을 지우면 그 버전으로 만든 기기는 쓸 수 없게 됩니다.

앱 센터: `앱` 구역 맨 위의 `앱 센터` 는 팀이 공유하는 `apps.json` 한 개에서 앱과 버전 목록을 읽어 보여 줍니다. 앱마다 버전과 기기를 고르고 `설치` 를 누르면 파일을 내려받아 같은 방식으로 검사, 변환, 설치, 실행하고 보관함에도 남깁니다. 처음에는 `앱 센터 주소` 를 열어 주소를 입력하고 `연결` 을 누릅니다(읽을 수 있는 주소만 기억합니다). 주소는 https 여야 하고 사내망 주소(`localhost`, 사설 IP, `.local`)는 http 도 됩니다. 로그인이 필요한 주소는 쓸 수 없으니 서명된 임시 주소(S3 presigned URL 등)나 인증 없는 사내 주소를 쓰세요. 파일 형식:

```json
{
  "name": "팀 앱 센터",
  "apps": [
    {
      "id": "com.example.pay",
      "name": "페이앱 Sandbox",
      "platform": "ios",
      "versions": [
        { "version": "25.8.0", "url": "https://builds.example.com/pay-25.8.0.ipa", "note": "main", "date": "2026-10-01", "sha256": "(선택) 파일의 SHA-256 소문자 16진수 64자" },
        { "version": "25.7.0", "url": "https://builds.example.com/pay-25.7.0.ipa" }
      ]
    },
    { "id": "com.example.pay", "name": "페이앱 Sandbox", "platform": "android", "versions": [{ "version": "25.8.0", "url": "https://builds.example.com/pay-25.8.0.apk" }] }
  ]
}
```

`platform` 은 `ios`(`.ipa`) 또는 `android`(`.apk`), `versions` 는 파일에 적은 순서 그대로(보통 최신이 위) 보입니다. `sha256` 을 적으면 내려받은 파일이 다를 때 설치하지 않습니다. 형식이 맞지 않는 앱이나 버전은 건너뛰고 몇 개를 건너뛰었는지 알려 줍니다. 빌드 서버가 이 파일을 갱신하게 해 두면(예: CI 가 새 빌드를 올릴 때 한 줄 추가) 새 버전이 앱 센터에 바로 나타납니다.

도구 구역:

- `딥링크 / 주소 열기`: 주소를 입력하면 열기 전에 종류(웹 주소, 앱 전용 스킴), 스킴, 호스트, 경로, 파라미터로 나눠 보여 줍니다. 열 수 없는 주소(`javascript:` 등)는 이유가 표시됩니다. `선택한 기기` 또는 `켜진 기기 모두`에서 열 수 있어서 iOS 와 Android 에 같은 링크를 한 번에 보낼 수 있습니다. 연 주소는 `최근 주소`에 남고, 이름을 붙여 `즐겨찾기` 로 저장할 수 있습니다(누르면 입력칸에 들어갑니다). Android 에서 그 주소를 처리하는 앱이 없으면 실패로 알려 줍니다. iOS 는 알려 주지 못하고 기기 화면에 안내가 뜰 수 있습니다.
- `화면 캡처`: 누르면 묻지 않고 `사진/Multibox` 폴더에 저장합니다. 한 기기를 캡처하면 클립보드에도 복사되어 Slack, Jira 에 바로 붙여넣을 수 있고, `열린 기기 모두 캡처` 는 열려 있는 화면을 한 번에 저장합니다. 기기 화면 위의 카메라 버튼도 같습니다. `캡처 폴더 열기` 로 Finder 에서 봅니다.
- `화면 녹화`: 기기 화면 위의 녹화 버튼(원 모양)을 누르면 시작하고 경과 시간이 보입니다. 다시 누르면 멈추고 `사진/Multibox` 폴더에 저장합니다(iOS 는 `.mov`, Android 는 `.mp4`). iOS 는 화면이 바뀔 때만 기록하므로 가만히 있는 화면은 아주 짧은 영상이 됩니다. Android 는 한 번에 최대 3분이고 넘으면 저절로 멈추고 저장합니다. 화면을 닫거나 기기를 끄면 그때까지의 녹화를 저장합니다.
- `기기 로그`: `로그 열기` 를 누르면 기기 화면 아래에 선택한 기기의 로그가 실시간으로 쌓입니다. `모든 앱` 대신 설치한 앱을 고르면 그 앱의 로그만 보고(iOS 는 실행 파일 기준, Android 는 앱이 실행 중이어야 하고 시작할 때의 프로세스 번호 기준), 레벨(전체, 정보, 경고, 오류)과 검색어로 거릅니다. 검색어를 `/정규식/` 으로 쓰면 정규식입니다(대소문자 무시). 사내 이벤트 로그처럼 특정 문자열이 찍히는 줄만 보고 싶을 때 쓰세요. `일시정지` 하면 화면이 멈추고 그동안의 줄은 `계속` 을 누를 때 반영됩니다. `지우기`, `복사`(보이는 줄)도 있습니다. 기기마다 탭이 하나씩 생깁니다. 로그를 연 채로 오른쪽에서 다른 기기 화면을 누르거나 왼쪽에서 다른 기기를 고르면 그 기기의 탭으로 바뀌고, 탭을 누르면 그 기기 화면이 선택되며 키보드 입력이 그 화면으로 갑니다(화면을 닫았다면 켜진 기기는 다시 엽니다). 보고 있지 않은 탭도 로그를 계속 받아 두고, 탭의 `x` 로 그 기기만 닫습니다. 앱, 일시정지는 탭마다, 레벨과 검색어는 모든 탭에 같이 적용됩니다.
- `기기 상태`: 선택한 켜진 기기의 `화면 모드`(밝게, 어둡게), `글자 크기`(5단계), `위치`(도시를 고르거나 위도, 경도를 직접 입력)를 바로 바꿉니다. `푸시 보내기` 는 iOS 시뮬레이터에서 서버 없이 푸시 알림을 보내는 시험용입니다(앱을 고르고 내용 JSON 에는 `aps` 가 있어야 하며, 앱이 알림 권한을 받은 상태여야 보입니다). `앱 데이터 지우기` 는 설치한 앱은 두고 저장된 데이터만 처음 상태로 되돌립니다(확인을 거칩니다. Android 는 권한도 함께 초기화됩니다).
- `웹 디버깅`: iOS 는 Safari 를 열어 줍니다. Safari 메뉴 막대의 `개발자용` 메뉴에서 기기 이름을 고르고 열린 페이지를 누르면 웹 인스펙터가 열립니다(메뉴가 없으면 Safari 설정의 고급에서 개발자용 메뉴 보기를 켭니다). Android 는 Chrome 의 `chrome://inspect` 를 열어 주니 기기를 찾아 `inspect` 를 누릅니다. 앱 안의 웹뷰는 앱이 디버깅을 허용한 빌드여야 보입니다.

기기 화면 조작:

- 화면을 클릭하면 탭, 누른 채 끌면 스와이프, 트랙패드나 마우스 휠은 스크롤입니다. 클릭한 기기가 파란 테두리로 표시되고 `선택한 기기` 가 됩니다.
- 화면을 클릭해서 포커스를 준 뒤 키보드로 입력합니다. iOS 는 키보드 설정이 한글이면 영문 자판 그대로 눌러 한글이 입력됩니다. Android 는 영문, 숫자, 기호만 입력되고 한글은 입력할 수 없습니다.
- 화면 위의 아이콘 버튼에 마우스를 올리면 설명이 나옵니다. 집 모양(`홈`), 왼쪽 화살표(`뒤로`, Android), 겹친 사각형(`최근`, Android)은 기기의 같은 버튼입니다. 창 모양(iOS)은 같은 기기를 Simulator 앱 창으로도 열고, 카메라는 캡처, X 는 화면만 닫고 기기는 켜 둡니다.
- 방금 설치한 iOS 앱이 알림 권한 팝업을 띄워 둔 상태에서 `홈` 을 처음 누르면 홈 화면으로 가지 않고 그 팝업이 닫힙니다(iOS 동작). 한 번 더 누르세요.
- iOS 조작은 Xcode 의 비공개 기능을 쓰기 때문에, Xcode 를 업데이트한 뒤 조작이 안 되면 기기 화면 아래에 안내가 뜹니다. 화면은 계속 보입니다. 개발팀에 알려 주세요.

진짜 폰(실기기):

- **iPhone (USB, 화면 보기만)**: 케이블로 Mac 에 연결하고 잠금을 풀어 `이 컴퓨터를 신뢰`를 누르면 `iOS` 구역 맨 위에 `실기기 USB · 보기 전용` 으로 나타납니다. 처음 한 번은 `허용하기` 를 눌러 카메라 접근을 허용해야 합니다(iPhone 화면을 카메라처럼 받기 때문입니다. 한 번 허용하면 앱을 업데이트해도 유지됩니다). 화면은 시뮬레이터처럼 앱 안에 뜨고, 화면이 움직일 때 초당 최대 30장 갱신됩니다.
  - 보기만 됩니다. 화면을 눌러도 기기는 반응하지 않으니 폰을 직접 만지세요. 앱 설치, 실행, 주소 열기, 캡처, 녹화, 로그, 기기 도구는 쓸 수 없습니다.
  - USB 로만 됩니다(WiFi 로 연결한 iPhone 은 보이지 않습니다). 폰이 잠기거나 케이블이 빠지면 화면에 안내가 뜨고, 다시 연결하면 몇 초 안에 이어집니다.
- **Android (USB 또는 WiFi)**: 폰의 `개발자 옵션`에서 `USB 디버깅` 을 켜고 케이블로 연결하면 `Android` 구역에 `실기기 USB` 로 나타납니다. 앱으로 돌아오거나 `새로고침` 을 누르면 목록이 갱신됩니다. 처음에는 폰 화면에 "USB 디버깅을 허용하시겠습니까?" 가 뜨는데, 허용하기 전에는 `확인 필요` 로 보입니다. WiFi 로 연결하려면 폰과 Mac 이 같은 WiFi 에 있어야 하고, 폰의 `개발자 옵션 > 무선 디버깅` 을 켠 뒤 터미널에서 `adb pair <주소:포트>` (폰에 뜨는 6자리 코드 입력)와 `adb connect <주소:포트>` 를 한 번 합니다. `adb` 는 `~/Library/Android/sdk/platform-tools/adb` 에 있습니다.
  - 앱 설치, 실행, 주소 열기, 캡처, 클릭과 스와이프, 홈, 뒤로, 최근 버튼을 가상 기기처럼 쓸 수 있습니다. 설치는 같은 앱이 이미 있으면 데이터를 지우지 않고 덮어씁니다.
  - 화면은 폰이 만든 영상(H.264)으로 받아서, 화면이 움직일 때 폰 화면 갱신율에 가깝게(초당 수십 장) 부드럽게 보입니다. 화면이 멈춰 있으면 거의 갱신되지 않는 것이 정상입니다. 폰의 영상 녹화 기능이 3분이 한계라서 영상은 3분마다 이어받는데, 화면이 움직이는 중이면 끝나기 전에 다음 영상을 미리 시작해 멈춤 없이 바꿉니다. 폰을 가로로 돌리면 1초 안에 가로 화면으로 바뀝니다. 영상을 쓸 수 없는 기기는 1초에 한 장 안팎의 이미지로 대신합니다.
  - 실기기는 사람의 폰일 수 있어서 자동으로 선택하지 않고, `켜기`, `끄기`, 이름 바꾸기, 지우기가 없으며, "모든 기기에 설치" 같은 한꺼번에 하는 동작과 기기 설정을 바꾸는 도구(어두운 화면, 글자 크기, 위치, 앱 데이터 지우기)에서 빠집니다. 설치하려면 목록에서 그 폰을 직접 고르세요.
  - 결제 화면처럼 보안 설정이 걸린 앱은 화면이 검게 보입니다.

실행할 수 없는 빌드는 이유와 함께 거부됩니다.

- iOS 시뮬레이터에는 시뮬레이터용으로 빌드한 앱(`iphonesimulator`)이 가장 정확합니다.
- 사내 배포나 Ad Hoc 으로 만든 실제 기기용 `.ipa` 는 앱이 알아서 시뮬레이터용 사본으로 바꿔서 설치합니다. 원본 파일은 그대로이고 화면에 안내가 나옵니다. 사본은 다시 서명한 것이라 푸시 알림, 앱 그룹, 키체인 공유 같은 기능은 실제 기기와 다를 수 있습니다.
- 스토어나 TestFlight 에서 받은 앱은 암호화되어 있어 실행되지 않으니 개발팀에 시뮬레이터용 빌드를 요청하세요.
- Android 는 `arm64-v8a` 가 들어 있는 APK 여야 합니다.

## 4. 자주 겪는 문제

| 증상 | 확인할 것 |
|---|---|
| 앱을 열 때 "열 수 없음" 이 나온다 | dmg 로 설치했다면 부록의 방법 1 로 다시 설치하거나 `xattr -dr` 를 실행합니다. Homebrew 로 설치하면 나오지 않습니다. |
| `Xcode.app 이 아니라 ... CommandLineTools 가 선택돼 있습니다` | `환경 점검` 탭의 Xcode 항목을 따릅니다. 터미널에서 직접 하려면 `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer` 를 실행합니다. |
| `simctl 을 실행할 수 없습니다` | `sudo xcodebuild -runFirstLaunch` 를 실행합니다. |
| `설치된 iOS 런타임이 없습니다` | `환경 점검` 탭의 iOS 시뮬레이터 항목을 따릅니다. 터미널에서 직접 하려면 `xcodebuild -downloadPlatform iOS` 를 실행합니다. |
| `arm64-v8a 시스템 이미지가 없습니다` | SDK Manager 에서 ARM 64 v8a 이미지를 설치합니다. x86_64 이미지는 Apple silicon 에서 쓸 수 없습니다. |
| `aapt2 를 찾지 못했습니다` | SDK Manager 에서 Android SDK Build-Tools 를 설치합니다. `환경 점검` 탭의 `Android Build-Tools` 항목에서도 확인합니다. |
| iPhone 이 `iPhone 의 잠금을 풀고 ... 신뢰` 안내로 나온다 | iPhone 잠금을 풀고 `이 컴퓨터를 신뢰` 를 누른 뒤 케이블을 다시 꽂고 `새로고침` 을 누릅니다. 케이블이 충전 전용이면 안 됩니다. |
| iPhone 이 `카메라 접근이 꺼져 있습니다` 로 나온다 | 시스템 설정 > 개인정보 보호 및 보안 > 카메라 에서 Multibox 를 켜고 앱을 다시 엽니다. |
| Android 실기기가 목록에 안 나온다 | 케이블이 충전 전용이 아닌지, 폰의 `USB 디버깅` 이 켜져 있는지 확인하고 `새로고침` 을 누릅니다. 터미널에서 `~/Library/Android/sdk/platform-tools/adb devices` 에 보이는지 보면 앱과 폰 중 어느 쪽 문제인지 알 수 있습니다. |
| Android 실기기가 `확인 필요` 로 보인다 | 폰 화면에 뜬 "USB 디버깅을 허용하시겠습니까?" 에서 허용합니다. 안 뜨면 케이블을 다시 꽂거나 개발자 옵션의 `USB 디버깅 인증 취소` 후 다시 연결합니다. |
| 카메라나 마이크를 쓰는 페이지에서 권한을 묻는다 | 시스템 설정 > 개인정보 보호 및 보안 에서 Multibox 를 허용합니다. |

## 부록. dmg 로 직접 설치

Homebrew 를 쓰지 않는다면 [릴리즈 페이지](https://github.com/cola9k1/multibox/releases/latest)에서 `Multibox-<버전>-arm64.dmg` 를 받아 엽니다. 이 앱은 Apple 의 서명을 받지 않아서, 받은 방법에 따라 처음 열 때 macOS 가 막을 수 있습니다. 브라우저, Slack, AirDrop, 메일로 받은 `.dmg` 에는 "내려받은 파일" 표시가 붙고, 앱을 복사하면 앱 안의 모든 파일에 그 표시가 따라옵니다.

DMG 안의 `먼저 읽어 주세요.txt` 에도 같은 내용이 있습니다.

### 방법 1. 터미널에 붙여넣기

1. DMG 를 연 채로 터미널 앱을 엽니다. (Spotlight 에서 "터미널" 검색)
2. 아래 두 줄을 복사해서 붙여넣고 Enter 를 누릅니다. 표시 없이 복사하므로 macOS 가 막지 않습니다.

   ```bash
   mkdir -p ~/Applications
   ditto --noqtn "/Volumes/Multibox/Multibox.app" ~/Applications/Multibox.app
   ```

3. Finder 에서 홈 폴더의 `Applications` 폴더를 열어 Multibox 를 실행합니다. 관리자 권한은 필요 없습니다.

### 방법 2. 터미널 없이

1. Multibox 를 `Applications` 로 끌어다 놓습니다.
2. 열어 보면 "열 수 없음" 안내가 나옵니다. 확인을 누릅니다.
3. 시스템 설정 > 개인정보 보호 및 보안 아래쪽의 `그래도 열기` 를 누르고 로그인 암호를 입력합니다. 이 버튼은 열어 보려고 시도한 직후 약 1시간 동안만 나타납니다. 관리자가 아닌 계정은 관리자 이름과 암호를 물을 수 있습니다.

끌어다 놓은 앱이 방법 2 로도 열리지 않으면 터미널에서 아래를 실행합니다. 반드시 `-r` 이 들어가야 합니다.

```bash
xattr -dr com.apple.quarantine /Applications/Multibox.app
```
